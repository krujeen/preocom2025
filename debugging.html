การเขียนโปรแกรมไม่ใช่แค่การทำให้โปรแกรมทำงานได้ แต่ต้องทำให้ มนุษย์ (ตัวคุณเองและกรรมการ) สามารถอ่านและทำความเข้าใจโค้ดของคุณได้ง่ายด้วย และเมื่อเกิดข้อผิดพลาด คุณจะต้องมีเครื่องมือและเทคนิคในการค้นหาต้นตอของปัญหานั้น

⚡

แก้บั๊กเร็ว

โค้ดที่จัดระเบียบดีช่วยประหยัดเวลาในการหาข้อผิดพลาด

1. แนวทางการเขียนโค้ดให้สะอาด (Clean Code)

"Clean Code" คือโค้ดที่อ่านง่าย, เข้าใจง่าย, และบำรุงรักษาง่าย แม้ว่าในการแข่งขัน สอวน. เราจะเน้นความเร็ว แต่การจัดระเบียบที่ดีก็ช่วยประหยัดเวลาในการแก้บั๊กได้มาก

📝1.1 การตั้งชื่อ (Naming Conventions)

หลักการ ดี ✅ ไม่ดี ❌
ตัวแปร studentScore, totalSum a, b, t
ฟังก์ชัน calculateArea(), findMax() func1(), process()
ค่าคงที่ const int MAX_USERS max_users
💡 หลักการ:

ใช้คำที่สื่อความหมาย เพื่อให้คนอื่นเข้าใจได้ทันทีว่าตัวแปรหรือฟังก์ชันนี้ทำอะไร

📐1.2 การเว้นวรรคและการเยื้อง (Indentation & Spacing)

✨ตัวอย่าง: การจัดรูปแบบที่ถูกต้อง

Good Code Style 💻 C++
#include <iostream> using namespace std; int calculateSum(int start, int end) { int total = 0; for (int i = start; i <= end; i++) { total += i; } return total; } int main() { int result = calculateSum(1, 10); cout << "Sum: " << result << endl; return 0; }
🔑 จุดสำคัญ:

• ใช้ Indentation (Tab หรือ 4 spaces) อย่างสม่ำเสมอ
• เว้นวรรครอบ ๆ ตัวดำเนินการ (= + <= ฯลฯ)
• แยกบรรทัดให้ชัดเจนระหว่างส่วนต่าง ๆ

💬1.3 การใส่ความคิดเห็น (Comments)

// ดี: อธิบายความตั้งใจและเหตุผล int maxAttempts = 3; // จำกัดการลองไม่เกิน 3 ครั้งเพื่อป้องกัน infinite loop // ไม่ดี: อธิบายสิ่งที่ชัดเจนอยู่แล้ว int i = 0; // กำหนดค่า i เป็น 0
📋 แนวทาง:

• อธิบาย ทำไม (Why) และ ทำอะไร (What) ไม่ใช่ ทำอย่างไร (How)
• หลีกเลี่ยง Comment ที่ซ้ำซ้อนกับโค้ด
• ใช้ Comment เมื่อโค้ดซับซ้อนหรือมีเหตุผลพิเศษ

2. เทคนิคการ Debugging (การค้นหาข้อผิดพลาด)

ข้อผิดพลาด (Bug) แบ่งได้เป็น 2 ประเภทหลัก:

⚠️Syntax Error

คือ: ข้อผิดพลาดไวยากรณ์ (เช่น ลืม ;)

การแก้: Compiler จะแจ้งให้ทราบและแก้ไขง่าย

int x = 5 // ← ลืม semicolon cout << x << endl;
🐛Logic Error

คือ: โปรแกรมทำงานได้ แต่ให้ผลลัพธ์ผิดพลาด

การแก้: ยากที่สุด ต้องใช้เทคนิค Debugging

for (int i = 1; i < 10; i++) { // ควรจะเป็น i <= 10 ถึงจะวน 10 ครั้ง }

เราจะเน้นการแก้ปัญหา Logic Error ด้วย 2 เทคนิค:

🖨️2.1 Print Debugging

วิธีพื้นฐานและเร็วที่สุด

คือการใช้ cout เพื่อพิมพ์ค่าตัวแปรสำคัญ ๆ ออกมาดูในช่วงเวลาต่าง ๆ ของโปรแกรม เพื่อติดตามว่าค่ามันเปลี่ยนไปอย่างไร

Print Debugging Example 💻 C++
#include <iostream> using namespace std; void process(int n) { int sum = 0; for (int i = 1; i <= n; i++) { sum += i; // >>> เทคนิค Print Debugging: พิมพ์ค่าเพื่อตรวจสอบทุกรอบ cout << "[DEBUG] i=" << i << ", current sum=" << sum << endl; } cout << "Final Sum: " << sum << endl; } int main() { process(3); return 0; }

⚠️ข้อควรระวัง

อย่าลืมลบหรือ Comment โค้ด Debugging ที่ใช้ cout ออกก่อนส่งคำตอบ!

🔧2.2 การใช้ Debugger ของ VS Code

เครื่องมือทรงพลัง

Debugger เป็นเครื่องมือที่ช่วยให้เรา หยุดการทำงานของโปรแกรม ชั่วคราว (Pause) เพื่อตรวจสอบค่าตัวแปรในขณะนั้น และรันโค้ดทีละบรรทัด (Step by Step)

🎯 ขั้นตอนการใช้ Debugger ใน VS Code:

  1. 1
    ตั้ง Breakpoint: คลิกที่ขอบด้านซ้ายของหมายเลขบรรทัดที่คุณต้องการให้โปรแกรมหยุด (จะปรากฏเป็นจุดสีแดง)
  2. 2
    เริ่ม Debug: ไปที่เมนู Run (รูปแมลง) หรือกดปุ่ม F5 (ถ้าตั้งค่าในชั่วโมงที่ 2 ไว้แล้ว)
  3. 3
    ตรวจสอบตัวแปร: เมื่อโปรแกรมหยุดที่ Breakpoint ให้มองไปที่แผง Variables (ด้านซ้ายมือ) เพื่อดูค่าปัจจุบันของตัวแปรทั้งหมด
  4. 4
    ควบคุมการทำงาน: ใช้ปุ่มควบคุมด้านบนหรือคีย์ลัด:
ปุ่ม คีย์ลัด การทำงาน
▶️ Continue F5 รันต่อไปจนกว่าจะเจอ Breakpoint ถัดไป
➡️ Step Over F10 รันคำสั่งปัจจุบันและไปที่บรรทัดถัดไป
⬇️ Step Into F11 เข้าไปในฟังก์ชัน (ถ้าบรรทัดปัจจุบันเป็นการเรียกฟังก์ชัน)
⬆️ Step Out Shift + F11 ออกจากฟังก์ชันปัจจุบันและกลับไปยังจุดที่เรียกใช้
🌟 ข้อดีของ Debugger:

การฝึกใช้ Debugger จะช่วยให้คุณประหยัดเวลาในการหาข้อผิดพลาดใน Loop หรือฟังก์ชันที่ซับซ้อนได้อย่างมาก

🏋️สรุปการปฏิบัติ

✅ ก่อนส่งโค้ด:

ตรวจสอบชื่อตัวแปร, การเยื้อง, และลบโค้ด Debugging ที่ไม่จำเป็นออก

🐛 เมื่อมีบั๊ก:

ลองใช้ Print Debugging ก่อนสำหรับปัญหาเล็ก ๆ ถ้ายังหาไม่เจอ ให้ใช้ VS Code Debugger เพื่อรันโค้ดทีละบรรทัดและติดตามค่าตัวแปร

🧩 โจทย์ฝึกหัด:

นำโค้ดการหาผลรวมในชั่วโมงที่ 6 มาลองตั้ง Breakpoint แล้วใช้ F10 (Step Over) รันทีละบรรทัดเพื่อดูว่าค่า sum เปลี่ยนแปลงอย่างไรในแต่ละรอบของ for loop

🔑จุดสำคัญที่ต้องจำ

  • Clean Code: ชื่อตัวแปรชัดเจน, การเยื้องสม่ำเสมอ, Comment ที่มีประโยชน์
  • Print Debugging: เทคนิคเร็วสำหรับปัญหาง่าย ๆ แต่อย่าลืมลบออกก่อนส่ง
  • VS Code Debugger: เครื่องมือทรงพลังสำหรับปัญหาซับซ้อน ใช้ Breakpoint และ Step Over
  • Logic Error: ยากกว่า Syntax Error ต้องใช้เทคนิค Debugging เพื่อติดตาม
  • ความเร็วในการแก้บั๊ก: โค้ดที่จัดระเบียบดีช่วยประหยัดเวลาในการหาปัญหา

🎯 ขั้นตอนต่อไป

หลังจากนี้ เราจะเข้าสู่หัวข้อการแก้ปัญหาพื้นฐาน ซึ่งจะทำให้คุณรู้ว่าโค้ดที่ถูกต้องอย่างเดียวไม่พอ แต่ต้อง เร็ว ด้วยครับ!

การเรียนรู้ Time Complexity และเทคนิคการเลือกอัลกอริทึมที่เหมาะสม!
